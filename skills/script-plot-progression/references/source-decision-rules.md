## 基本原则

把原剧本视为剧情因果、人物关系、顺序和原始对白的基线。只让明确确认的导演决定覆盖基线。让每项正式事实都能追溯到来源，不根据常识补写剧情。

将“来源权威性”和“来源新旧”分开判断。较新的讨论稿不等于已经确认；较旧的锁定决定也可能被当前明确确认覆盖。

## 来源层级

从高到低使用：

1. 用户在当前任务中明确确认的最终决定。
2. `DecisionLedger` 中状态为 `CONFIRMED` 的导演决定。
3. 已锁定项目事实，包括人物关系、能力、场景和道具状态，以及上一集 `EpisodeHandoff`（`EPISODE_HANDOFF`）的继承项与禁止重置项。
4. 原剧本。
5. 暂定资料、个人想法、备选和讨论稿。
6. 通用知识和模型推断。

只允许第 1-3 层在明确影响范围内覆盖第 4 层。禁止第 5-6 层覆盖第 1-4 层。

同一层级来源发生冲突时，不按文件日期、篇幅或措辞强弱自行裁决。寻找明确的确认记录；没有记录就进入 `HUMAN_GATE`。

## 确认状态

使用以下状态：

| 状态 | 识别方式 | 正式产物处理 |
|---|---|---|
| `CONFIRMED` | 明确写有“确认、最终版、锁定、按此执行、采用此方案”等，或用户当前明确确认 | 可以应用 |
| `TENTATIVE` | “想法、建议、也许、可以考虑、备选、草稿、导演构思”等 | 不应用，只记录待确认 |
| `REJECTED` | 明确写有“不采用、否决、删除这个方案、不要这样处理”等 | 隔离，禁止进入产物 |
| `CONFLICT` | 两个锁定来源互斥且没有新裁决 | 停止受影响范围 |
| `UNKNOWN` | 缺失确认状态或资料不足 | 不应用，不猜测 |

不要仅凭标题中的“方案”“新版”判断为 `CONFIRMED`。确认必须来自明确语句或结构化状态。

## 剧本基线

- 保持原剧情事件顺序。
- 保持原始台词逐字一致，包括标点、称呼和疑似错别字。
- 保持说话人和台词位置。
- 保持原文明确的人物关系、已知信息、道具状态和行动结果。
- 保持伏笔揭露时机，不提前把后文信息写入前置状态。
- 不把场景说明中的模糊空间词扩写成具体镜头站位。

把纯格式、页眉页脚、编号或不含剧情信息的排版标记排除在 BEAT 外，但保留其来源定位价值。

## 导演覆盖

应用导演覆盖前，确认以下五项：

1. 有稳定 `decision_id`。
2. 状态为 `CONFIRMED`。
3. 能定位被覆盖的剧本范围或事实字段。
4. 能描述确认后的唯一结果。
5. 能计算受影响场次或 BEAT。

记录：

```json
{
  "decision_id": "DEC-017",
  "overrides_source": "SCRIPT-E01-V1:L120-L126",
  "original_value": "父亲拒绝查看通知书",
  "confirmed_value": "父亲拿起通知书查看",
  "affected_beats": ["BEAT-E01-S03-004"],
  "status": "CONFIRMED"
}
```

只修改明确覆盖的内容。不要顺带调整未提及的台词、人物动机、前后事件或情绪强度。

如果导演只否决原方案但没有给出替代结果，把该范围设为 `HUMAN_GATE`；不要自行补一个替代剧情。

## 录音和讨论纪要

不要在 S02 内转写音频。只接受由上游提供的转写文本、时间码和确认状态。

从转写或纪要中区分：

- 最终决定：“就这样”“按第二版”“确定让父亲拿起来”。
- 建议：“也许可以”“要不要试试”“我倾向于”。
- 否决：“这个不要”“不拍这个”“上一版作废”。
- 讨论：“如果……会不会……”；没有结论时保持暂定。

不要把说话人的自信语气当成确认。不要把会议中无人反对当成确认。

## 冲突处理

遇到冲突时：

1. 列出互斥来源及精确定位。
2. 描述它们对同一事实给出的不同结果。
3. 计算最小受影响范围。
4. 保持不受影响场次继续可用。
5. 将受影响原文逐项登记为 `PARTIAL` 或 `OMITTED`，并计入覆盖总数。
6. 将受影响范围置于 `HUMAN_GATE`。
7. 提出一个可以直接裁决的问题。

合格问题：

```text
第 3 场以原剧本“父亲拒绝查看通知书”，还是 DEC-017 讨论稿“父亲拿起通知书”为准？当前没有找到已确认结论。
```

不合格问题：

```text
这里该怎么拍？
```

后者超出 S02 职责，也没有暴露真实冲突。

## 未知和结构化推导

使用 `DERIVED` 只表示对原文事实进行无新增的结构化表达，例如：

- 原文写“父亲看完通知书抬头”，可以推导结束状态为“父亲已经看过通知书”。
- 原文连续写“女主递出通知书；父亲接过”，可以结构化为道具归属从女主转移到父亲。

不要把以下内容标成 `DERIVED`：

- 原文没写但“通常会发生”的反应。
- 根据人物类型猜出的隐藏动机。
- 为了镜头连续而补出的走位。
- 为了增强戏剧性添加的停顿、台词或道具。

无法确认的内容写成 `UNKNOWN`。若未知内容影响因果、人物身份、对白说话人或结果，标记 `blocking: true`；否则保持非阻断，不让它污染已知事实。

## 禁止推断

- 禁止因人物是“父亲”就推断其关心、严厉或愧疚。
- 禁止因角色沉默就推断其同意、震惊或谋划。
- 禁止因道具出现就推断谁拥有、谁使用或它有何能力。
- 禁止因场景类型推断人物站位和镜头方向。
- 禁止用后续剧情知识提前改写前一 BEAT 的人物已知信息。
- 禁止把失败生成案例、电影语言规则或模型限制升级为剧情事实。
