## 连续性目标

让前一 BEAT 的结果成为后一 BEAT 可成立的起始条件。只追踪剧情需要的状态，不设计屏幕左右、轴线或机位关系。

不要要求前后状态逐字相同。比较事实是否兼容，以及变化是否有来源支持。

## 四类状态

在 `start_state`、`end_state`、`scene_start_state` 和 `scene_end_state` 中使用：

```json
{
  "characters": {},
  "props": {},
  "environment": {},
  "knowledge": {}
}
```

### characters

记录：

- 是否在场或明确处于画外。
- 与剧情相关的位置或姿态，如“站在门口”“倒在床上”。
- 伤势、束缚、昏迷、能力启用等影响行动的状态。
- 原文明确的服装或身份变化。

不要记录景别、画面左右、机位投影或焦点。

### props

记录：

- 道具主人或当前持有者。
- 持物手，仅在原文或锁定事实明确时记录。
- 放置位置。
- 完整、损坏、打开、关闭、激活或耗尽状态。
- 是否已交接、掉落或遗失。

### environment

记录：

- 门窗开关、停电、火灾、坍塌等剧情相关环境变化。
- 影响人物行动的天气或地面状态。
- 人物已经进入或离开的剧情空间。

不要补写灯位、色温或拍摄氛围。

### knowledge

记录：

- 哪个人知道或不知道某项关键信息。
- 某项身份、秘密、结果是否已揭露。
- 台词或可见事件让谁获得新信息。

不要把观众知道的信息自动赋给人物。

## 相邻 BEAT 检查

对每对相邻 BEAT 执行：

```text
前一 end_state
+ 前一 continuity.open_actions
→ 后一 start_state
```

确认：

- 不存在无来源的状态重置。
- 不存在未完成动作被当作已完成。
- 不存在已经完成的动作在下一 BEAT 重复开始。
- `must_carry_forward` 在后续仍被继承，直到有来源支持它改变。
- 新状态能够追溯到触发、行动、反应或对白。

## 人物连续性

拦截：

- 人物无入场事件却突然在场。
- 人物无离场事件却从连续场景消失。
- 昏迷、受伤、被束缚等状态无事件支持地恢复。
- 人物身份、关系或能力在没有揭示与决定的情况下改变。
- 后一 BEAT 使用人物尚未获得的信息行动。

场景转换可以使人物位置发生变化，但仍需原文支持其出现在新场景。

## 道具连续性

按以下链条追踪：

```text
初始归属
→ 接触
→ 交接/使用/掉落
→ 最终归属和位置
```

拦截：

- 道具切到下一 BEAT 自动换手。
- 掉落或损坏后自动回手或复原。
- 道具尚未出现就被人物使用。
- 同一唯一道具同时处于两个互斥位置。
- 关键道具在没有交代的情况下消失。

原文没有写持物手时，不根据习惯补左右手。

## 信息连续性

把关键台词、文件内容、目击事件和身份揭露视为信息状态变化。

检查：

- 谁直接听见、看见或被告知。
- 谁只是在场但不一定获得信息。
- 谁处于画外或被明确排除。
- 信息在什么 BEAT 后才可用于人物决定。

不要让人物根据后文信息提前反应。不要把旁白或观众视角自动变成人物知识。

## 动作连续性

把动作的完成阶段写清：

- `open_actions`：仍在进行或下一 BEAT 必须接续。
- `must_carry_forward`：已经形成且必须保留的状态。

示例：

```json
{
  "must_carry_forward": ["通知书已放在父亲面前"],
  "open_actions": ["父亲正准备伸手拿起通知书"]
}
```

下一 BEAT 不得重新写女主“拿出通知书”，除非原文明确她重新拿回。

## 跨场连续性

场次变化不代表所有状态重置。继承：

- 人物已经知道的信息。
- 未解决的伤势、关系和任务。
- 随身或已交接的关键道具。
- 已确认持续生效的能力或限制。

允许因为明确时间跳跃而改变状态，但必须记录来源。原文只写“第二天”而没有交代伤势恢复时，不自行判定已经痊愈。

## 未知状态

区分：

- `UNKNOWN`：资料没有说明。
- `CONFLICT`：资料给出互斥说明。
- 不相关：该维度不影响当前或后续剧情，不必记录。

不要用空字符串表示未知。使用 `unknowns` 项并说明是否阻断。

阻断示例：台词说话人未知、关键道具归属冲突、人物是否已经知道秘密无法确定。

非阻断示例：剧本没有说明桌子材质，而该信息不影响剧情。

## 问题路由

- 原剧本缺页或来源冲突：`HUMAN_GATE`。
- S02 遗漏或误写状态：由 `QA:PLOT` 返回 S02 局部修复。
- 需要新增过场解决跳变：不由 S02自行添加，提交导演确认。
- 屏幕左右、轴线或镜头承接：交给 S03，不写入剧情连续性事实。
